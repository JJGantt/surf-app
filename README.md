# surf-app

The surf app: an iPhone app and its Apple Watch companion for Mayport Poles — the surf heat map,
the live readings (measured wind, buoy swell) beside what Surfline's model says, and a short-term
forecast that folds the live readings in.

Its own product, so its own repo. It shares a backend with StatusHub rather than code:

| piece | where |
|---|---|
| Surfline forecast capture, NDBC water/wind archive | `surf-report` (the Pi's crontab) |
| live wind, surf alarm, the APIs this app reads | `status-hub/server` on Fly (`jared-status-hub`) |
| the iPhone and watch apps | here |

**Gnarcast** in App Store Connect (app id `6814910411`, SKU `surf-app`). Bundle ids
`com.jaredgantt.surf` (iPhone) and `com.jaredgantt.surf.watchkitapp` (the watch app, shipped inside
the iPhone app, which is why one record covers both). TestFlight group `internal_main` has access to
every build and holds the developer's own tester account; a build uploaded with no group reaches no one. A tester
goes in by CREATING the tester with the group in its relationships (`POST /v1/betaTesters`) —
adding the account's existing tester record to the group is refused ("Tester(s) cannot be assigned").

## What is here

| | |
|---|---|
| `App/` | the iPhone app: the hub's `/surf` page in a web view, full screen — the live readings and the surf heat map, pushed live by `/api/surf/stream`. Nothing else, and nothing to sign in to |
| `Watch/` | the watch app: reads `/api/surf/live` when it comes to the front — rating now, measured wind against the forecast, the next hours, each buoy |
| `Shared/Hub.swift` | the hub's address and the feed's types |
| `project.yml` | the Xcode project, generated by `xcodegen generate` (the `.xcodeproj` is not committed) |
| `tools/icon.py` | draws the app icon into both asset catalogs |

Everything the apps show is computed by the hub (colours, labels, compass points); the apps only lay
it out.

**No sign-in.** The surf page and the surf feeds are public (status-hub `server.js`, `PUBLIC_SURF`):
a forecast, the measured wind and the buoys, all of it public NOAA and Surfline data. The rest of the
hub stays behind its password.

## Building

**Build on the Mac first.** `tools/testflight.sh` archives, signs and uploads to TestFlight from
the owner's Mac in about three minutes. It signs as Xcode does, from the login keychain; profiles come
from the App Store Connect API key, not an Xcode account login. The simulator build proves the plists, the icon and
the watch embedding without signing anything:

    xcodegen generate
    xcodebuild -project Gnarcast.xcodeproj -scheme Gnarcast -destination 'generic/platform=iOS Simulator' \
      -derivedDataPath build CODE_SIGNING_ALLOWED=NO build

**The backup** is `.github/workflows/testflight.yml` (manual dispatch, or an `ios-*` tag), the same
build on a rented Mac for when that one is away. GitHub bills macOS minutes at ten times Linux's against
the free allowance. It signs with this repo's OWN distribution certificate (secrets `IOS_DIST_P12` /
`IOS_DIST_P12_PASSWORD`, expires 2027-09-22) and the account's one development certificate (`IOS_DEV_P12`, shared with
status-hub): with no development identity in the runner's keychain, automatic signing mints a new one
every run and the account fills up. `ASC_KEY_P8` is the App Store Connect API key.
